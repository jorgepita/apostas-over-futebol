## Outstanding Issues

- None new in `05_Known_Issues.md` — this phase is a feature addition, not a bug fix for an existing diagnosed issue.
- **Not yet possible to validate:** a real upload/restore cycle against an actual Cloudflare R2 bucket. Everything in this session was validated against `FakeR2Client` (an in-memory double) or monkeypatched GitHub primitives — zero real network I/O to R2 occurred, because no bucket or credentials exist. This is explicitly flagged, not silently assumed to work.
- **Documented, not fixed (accepted design limitation):** `backup_index.py`'s R2 catalog write is a read-modify-write, not a compare-and-swap. A genuinely rare race between two near-simultaneous backup operations could drop one index entry from the catalog — the underlying R2 object would be unaffected and rediscoverable via `rebuild_index_from_r2()` regardless, so this is a discoverability gap, not a data-loss gap. Accepted given this project's actual backup cadence (a handful of backups per day from callers essentially never both mid-request at once); see ADR-020's Consequences.
